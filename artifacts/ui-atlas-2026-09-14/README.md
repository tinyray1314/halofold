## 采集方法

复制当前工作区 `Sources` 到 `/tmp/halofold-ui-atlas-capture`，编译原生 SwiftUI / AppKit 视图，使用 `HALOFOLD_NO_CODEX_TODO` 隐藏分发版排除的实验功能。只在副本注入演示状态和独立窗口宿主；未重新绘制 UI，也没有把原生界面仿制成网页。

采集程序不调用产品的 `start()`，不启动真实 Codex 监测、日程后台计时或音频播报。各场景数据使用 `HALOFOLD_SUPPORT_DIR` 指向独立临时目录，功能设置使用 `local.halofold.ui-atlas.fixtures`，应用拥有独立 Bundle ID。真实产品的设置、计划和便签没有被写入。

主要静态状态由实际模型方法或原生视图动作进入；菜单、滚动内容、退出提示与录像通过 CUA 的真实点击补拍。程序状态演示与功能测试不同，不能证明真实定时、网络、睡眠或外部跳转正确。

## 范围和限制

- 这是当前工作区底稿，包含采集前已有的未提交日程修改，不是已发布 DMG 的独立验证。
- 窗口居中展示；顶部收起视图以两侧原生控件组合，中间黑块是占位。未验证真实刘海尺寸、菜单栏覆盖、自动收起、外接显示器、全屏应用和全局快捷键。
- 固定中文、默认开启功能；未穷举所有语言、屏幕尺寸、每种功能开关组合或每个数据长度。
- 系统文件选择、授权对话框、录音、音色包生成/下载及真实 Codex 任务跳转未触发。实验性「发现待办」不在本册主范围。
- `schedule-adjust.png` 在采集窗口中出现浅底浅字冲突，可读性异常。已保留原样并在页面注明；需要用正式 NSPanel 窗口复核，尚未归因为产品缺陷。
- 例行表单首屏和滚动补拍使用不同数量的演示事项，分别用于观察入口位置和完整表单，不应当作逐帧动画。
- 活动结果区使用移除运行任务的演示数据，方便观察待处理、完成、中断和用量，并非同一满列表的滚动截图。

## 重建工具

在仓库根目录运行：

```sh
python3 artifacts/ui-atlas-2026-09-14/tools/prepare_capture.py
swift build --package-path /tmp/halofold-ui-atlas-capture -Xswiftc -DHALOFOLD_NO_CODEX_TODO
python3 artifacts/ui-atlas-2026-09-14/tools/capture.py
python3 artifacts/ui-atlas-2026-09-14/tools/build_atlas.py
```

`capture.py` 依赖 screenshot 技能的脚本副本 `/tmp/halofold-screenshot-skill`。本次将技能文件 CRLF 转为 LF 后使用，未修改技能安装文件。临时目录失效后需重新从技能目录准备副本，并先执行权限预检。菜单、滚动和录像属于交互补拍，默认批处理不重建它们。
