# Halofold UI 升级：本地实现与验收

2026-09-14。本轮在用户认可自查方案后实施。保留原生深色紧凑面板；工作空间尺寸仍为 510 × 443。修改前后对照见 [验收页](index.html)，修改前全景册仍保留。

## 实现结果

| 原问题 | 本轮改变 |
|---|---|
| 跨工作空间、进入设置后丢失日程草稿 | 保留三个工作空间的原生视图实例、草稿与滚动状态；隐藏空间不接受点击，也不出现在辅助功能树中 |
| 待处理事项被运行列表挤下去 | 待处理原因固定在活动页上部；运行列表默认 3 项，可展开全部 |
| 有旧缓存时异常原因不显示 | 异常优先显示真实原因；数据来源问题进入通用设置，用量错误提供重试 |
| 删除恢复缺失或恢复成新记录 | 便签、单项日程、例行事项统一 8 秒撤销；恢复原 ID、内容、时间与专注记录；重复日程删除后续先确认影响范围 |
| 导航位置随空间变化 | 固定「活动 / 便签 / 日程」，右侧固定设置、收起、应用菜单；退出收进应用菜单 |
| 编辑表单在列表不同位置 | 新建、编辑统一在列表前，进入编辑自动滚动；显式显示日期、重复规则，时长可直接输入 |
| 今天的新建默认 09:00 | 取下一个五分钟刻度；跨午夜时日期一起前进；其他日期保留 09:00 |
| 大倒计时挡住切换 | 各空间持续显示紧凑状态条，点击打开详细计时；切换不调用暂停/完成/重新开始 |
| 设置层级和保存语义不清 | 明确自动保存、单一返回入口；音量前置；提醒内容按需展开；低频数据与演示分组 |

单次修改重复日程时，重复规则保持只读，并提示通过「修改后续」调整整组。未保存的新日程切换日历日期时保留标题等输入。草稿保留范围是当前应用会话，尚未加入跨重启草稿恢复。

## 实际验收

- 原生普通演示窗口：新增草稿 → 设置标题和 45 分钟 → 便签 → 日程 → 设置 → 返回。标题与时长均保留。随后保存，列表出现对应日程，编辑表单关闭。
- 输入通过原生可访问性接口写入；本轮未据此宣称中文输入法或键盘快捷键已经完成真机验证。
- 原生专注状态：切到便签，倒计时继续减少；点击状态条进入详情。另从例行事项点击状态条，能正确进入详细计时。
- 专注详情打开后，辅助功能树中不再暴露底层日程列表按钮；顶部工作空间导航仍可访问。
- 原生便签：删除后点击撤销，原便签标题和富文本内容恢复。
- 原生重复日程：删除本次，日期计数从 2 变为 1；撤销后恢复为 2，原日程重新出现。
- 原生批量删除：确认提示显示项目名称、开始日期与后续范围；点击取消后记录保留。本轮未执行最终批量删除。
- 完整配置：`swift test`，71 项通过。
- 正式功能配置：`swift test -Xswiftc -DHALOFOLD_NO_CODEX_TODO`，68 项通过。3 项实验性待办提取测试随该功能一起排除。
- Xcode Debug：`CODE_SIGNING_ALLOWED=NO` 构建通过。
- `git diff --check` 通过。

新增的 6 项测试覆盖：最后一张便签删除后持久化再恢复；恢复时保留新输入；已完成日程的专注历史完整恢复且不回滚其他新增；生成型与已修改重复日程恢复；例行事项身份与时间恢复；默认时间与跨午夜边界。

## 文件与复核

- `index.html`：8 组前后对照、行为验收和本轮截图。
- `screenshots/`：隔离演示数据的原生截图。
- `source-manifest.json`：本轮采集源文件指纹、构建方式与隔离目录。
- `implementation.patch`：相对本轮开始时的工作区副本生成，仅包含本轮改动。
- `changed-files.json`：本轮变更的 10 个源码/测试文件。
- `validation/`：最终测试、Xcode 构建日志。
- `tools/`：独立采集宿主和验收页生成脚本。

此前已存在的日程/提醒修改保留。本轮没有提交、合并、安装替换或发布；没有操作日常版本的真实日程和便签数据。

本轮 UI 在独立原生窗口中居中验收。真实刘海位置、多显示器、长时间后台功耗、锁屏后提醒、实际音频输出，以及签名安装包发布属于后续真实安装环境验收范围。新旧截图使用不同采集时间，时间文字会有差别。
